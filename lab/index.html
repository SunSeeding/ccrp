01

这里有字谜

Riddle Intake · 开源情报式的情报源

把站点当成一个开源情报收集系统的情报源：用户或 Agent 可以提供链接、PDF、书页扫描、图片等线索，持续丰富字谜库。每条入库都带出处、抓取时间、片段哈希、许可与去重结论；模型创作与模型解析明确标注 no_url，绝不伪造链接。

还没想清楚：待想清楚：提交者身份与可信度、版权与许可、去重与一谜多底、质量闸门、以及如何与已冻结的 100 字数据隔离。
02

大模型擂台

Model Arena · 一次评测与一张榜单

由网站出题给大模型，本质上就是一次大模型评测：统一题集、统一提示词、统一判分，产出榜单与分层结果。另设「模型自己出题、全新会话自己答」的闭环赛道，把生成能力与求解能力分开量。

还没想清楚：待想清楚：论文已裁定现有公开切片不具备排名效度，必须先重建 1000 条分层冻结 test 集；还要解决记忆污染、多次采样方差、调用成本与榜单版本化。
03

Agent Forum

Agent-only Forum · 智能体的论坛

只允许 Agent 注册发贴的论坛，灵感来自 ClawBook。人类只读：议题围绕谜面、解题链、评测结果与反例；帖子本身可以成为新的语料与情报源，反哺第一条「这里有字谜」。

还没想清楚：待想清楚：Agent 身份与凭据、发帖协议与速率、如何避免自说自话与刷榜、内容审核，以及和擂台、情报源之间的数据边界。
04

解谜语法

Riddle Solving DSL · 描述思维链的数据格式

创造一种 Domain Language / 数据格式，专门描述解字谜的思维链，让「怎么想到的」可记录、可比较、可回放，而不是只留一个谜底和一段事后解释。例如谜面「玉无瑕疵」：第 1 步分解「玉」这个汉字，记为 Destructure 玉。

Riddle("玉无瑕疵")
  ├─ Destructure 玉 → 王 + 丶
  ├─ Parse 无瑕疵 → 去「丶」
  └─ Compose → 王

上例仅为示意，非正式语法定义；「王」是常见谜底，字理以权威字典为准。

还没想清楚：待想清楚：算子集合、拆形/会意/谐音三类的表达力、与 IDS 字形对齐、ICL 示例互操作，以及怎样验证一条链不是事后编造。
这几条不是路线图，也不是承诺，只是给未来的自己留的便签： 想到细节了再实现，没想到就一直放这儿，提醒自己这个项目还能往哪走。
